# Validation and record copies

Mobile numbers in registration, patient editing, self-service profiles, patient contacts and supplier contacts must contain exactly **10 ASCII digits**, without spaces, country codes, punctuation or letters. Browser input constraints, API validation and PostgreSQL check constraints enforce this rule. Migration 014 converts existing `+91` values only when they contain an exact ten-digit subscriber number; other invalid existing records cause the migration to fail for review, rather than silently losing digits. The SMS transport adds `+91` to the validated number when composing an invitation. Optional contact numbers may remain null.

Name, email and DOB fields also have browser length/date constraints. Required fields remain marked with an asterisk. Server and database validation remain authoritative when browser controls are bypassed.

Appointments, prescriptions, invoices (including payment receipts) and admission records have **Print** and **Download** controls. New appointment, prescription, invoice/payment and admission saves open a confirmation with these controls. Existing records retain their controls in the corresponding lists; clinicians can find prescription copies in Clinical workspace, and patients can find their own copies in My care, My appointments and My invoices.

Print opens the browser's print dialogue. Choose **Save as PDF** there for a PDF file. Download saves a standalone UTF-8 **HTML document**, which preserves patient names and instructions in any language and can be opened or printed offline without an internet connection. It is explicitly not a direct PDF download. Downloaded copies contain private patient information and reflect the record status and balances when generated; they do not create new payments or change prescriptions.

Record copies are generated from server-side persisted data. The endpoint checks the signed-in role, and patient accounts receive only their own records. Volunteers cannot obtain clinical documents; nurses cannot obtain billing documents. Mobile visibility in copies follows the existing field permissions, so billing-only and pharmacy-only accounts retain the mobile mask. Print/download requests are recorded in the activity log. User-entered text is HTML encoded. The download has no scripts or external resources, and print layout removes the application navigation and buttons.

Overviews now have next-step summaries, role-specific metrics and workspace cards. Patients see their next visit, care/invoice shortcuts and contact details. Nurses see inpatient/bed workspaces; volunteers see their assignments and overdue work. Admin, doctor, pharmacy and billing summaries follow their actual permissions. A **Go to a page** selector is available throughout the signed-in application.
